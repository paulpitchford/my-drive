## Question

Does device-code sign-in work for personal Microsoft accounts with our app registration
(open question Q2)? ADR-0010 offers `mydrive login --headless` through the paste flow and
offers device code only if this gate shows it works. abraunegg's documentation says device
code is not allowed for personal accounts unless Microsoft authorises the app; no Microsoft
source for that was found.

## Method

The program is `crates/mydrive-graph/examples/g5_device_code.rs`. In order, it:

1. Posts to the identity platform's `oauth2/v2.0/devicecode` endpoint under the `common`
   authority, with the compiled-in client ID and the scopes `Files.Read offline_access
   openid` (the same read-only set as G1; `openid` grants no access to Graph or to files).
   A refusal is reported by its OAuth error code and `AADSTS` numbers, and the program
   stops.
2. Shows the verification address and the user code on standard error, then polls the
   token endpoint with the RFC 8628 device-code grant at the interval the platform names
   (5 s if it names none), adding 5 s on each `slow_down`. It stops on
   `authorization_declined`, `expired_token`, any other error, or when the code's lifetime
   ends.
3. Once tokens arrive, reads the `tid` claim of the ID token (for display only, signature
   not checked), maps Microsoft's public consumer tenant
   `9188040d-6c67-4c5b-b112-36a304b66dad` to "personal" and any other tenant to "work",
   prints the kind and the tenant ID on standard error, and sends nothing to Graph until
   the owner types `yes`.
4. Sends one `GET /me/drive` with the access token and reports its status, error code and
   `driveType`.

The report, on standard output, holds the outcome, the number of `authorization_pending`
and `slow_down` answers, which tokens came back, the scopes granted, the kind of account
and the Graph check. It holds no token, no device code, no user code, no tenant ID and no
other account identifier. The verification address, the user code, the confirmation
prompt and any error description from the identity platform (which can name the account)
appear on standard error only and are not part of the report. Tokens are held in memory
for the length of the run and never stored.

## How to run it (owner)

On the build machine, from a checkout of this branch.

1. `mise install` (once), then
   `mise exec -- cargo build -p mydrive-graph --example g5_device_code`.
2. Run, keeping the report separate from the prompts:

   ```sh
   mise exec -- cargo run -q -p mydrive-graph --example g5_device_code > g5-personal.md
   ```

3. If the platform refuses the device-code request, the program stops at once and the
   report says why. That is a result: go to step 6.
4. Otherwise standard error shows an address (normally `https://microsoft.com/devicelogin`)
   and a code. Open the address in a browser on any device, enter the code, and sign in
   with the **personal** account. The program waits; it gives up when the code expires
   (about 15 minutes) or on Ctrl-C.
5. When it prints the account kind and tenant ID, check that it says
   `personal account, tenant 9188040d-6c67-4c5b-b112-36a304b66dad`. Type `yes` only if it
   does; anything else stops before any request reaches Graph.
6. Read `g5-personal.md`. Check it holds no name, address, code or ID before copying
   anything from it. Paste its contents under "Observations: personal account" below, with
   anything the browser showed (for example an error page and its `AADSTS` code).
7. For a work account: repeat steps 2 to 6 with `> g5-work.md`, signing in with a work or
   school account of a tenant the owner administers or is a member of. At step 5 check that
   the kind is `work` and the tenant ID is the one expected; type anything but `yes` if it
   names a tenant where the owner is only a guest. If no tenant is available, write
   "pending: no tenant available" under the work-account heading.
8. Delete the report files when their contents are in this document. To withdraw the
   consent, use the account's "apps and services" page.

The program exits 0 when it reached the Graph check, 1 when it stopped earlier (the report
says why), and 2 for a bad command line. `--help` lists the options.

## Conclusion

*Pending.* How the report is to be read:

| Observation | Meaning |
|---|---|
| `device-code request: refused` (for example `unauthorized_client`, `AADSTS70002`) | Device code is not available to this registration as configured; check whether the registration's "allow public client flows" setting is off before concluding it is a personal-account restriction |
| Request accepted, sign-in refused in the browser for the personal account | Device code is not offered to personal accounts with this registration: abraunegg's claim holds |
| `sign-in: completed` and `Graph check: GET /me/drive answered 200` | Device code works for personal accounts: ADR-0010 may offer it as a headless flow |
| `declined by the user` or `the code expired` | No result; run again |

## What it means for ADR-0010

*Pending.* Until this gate passes, ADR-0010 offers headless sign-in only through the paste
flow and does not offer device code. The lead changes the ADR from the findings; this
document does not.

## What could not be verified

- Nothing has been run against the real service yet.
